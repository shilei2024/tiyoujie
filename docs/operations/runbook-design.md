日期：2026-10-22。状态：设计；**没有可执行部署/备份脚本，没有云端操作或演练结果**。Phase 1 创建基础脚本，Phase 7 用实际目标环境补齐并验证。本文件不要求用户执行不存在的命令。

## 环境与资源

dev/test/staging/prod 使用不同 DB、账号、卷、bucket/prefix、秘密和 Compose 项目名。测试数据库凭证不得访问生产，测试存储必须临时隔离。测试脚本校验环境标识，遇 prod/未知 DSN 拒绝破坏性操作；数据库名含 test 不是唯一安全依据。

拟选 Linux 长期支持发行版，具体由目标主机决定。资源规划初始假设为 4 vCPU、8 GiB、至少 80 GiB SSD、一个低并发 Worker、外部 AI 推理；这不是容量实测或购买建议。2 vCPU/4 GiB 仅可作为受限预发布候选。按图片像素上限、同时任务、PDF 内存和数据库/备份增量压测后再确定配额。云服务器当前资源/费用未知。

公网仅反向代理 443/必要的 80 证书验证，SSH 来源受限；DB/Redis 不公开。静态资源可以公共缓存，媒体/导出禁止公共缓存和公开桶。Linux 容器使用非 root 账户、必要卷和资源限制；Worker 限并发/超时，数学验证和 PDF 分开进程资源边界。

## Phase 1 计划脚本契约

| 将创建的入口 | 行为 | 安全约束 |
| --- | --- | --- |
| 配置预检 | 验证环境、强制秘密、端口和服务依赖 | 不打印秘密，不自动补默认生产 Key |
| 本地启动 / 健康检查 | 专用 Compose 项目，live/ready，日志 | 不触及已有容器或宿主 DB，不自动灌种子 |
| 显式迁移入口 | 指定环境/DB，迁移计划与前后检查 | 不在每次生产启动自动执行危险迁移 |
| 隔离测试入口 | 专用 test profile、临时存储、退出码 | 清理只针对经解析确认的本次测试卷 |

`.env.example` 只列环境变量名和空值/无效占位；真实 .env 被忽略。平台 Provider 秘密与 BYOK 主密钥独立，只有必要进程挂载；启动脚本不生成并输出生产密钥。平台 AI 无凭证/预算时 disabled，不影响人工错题功能。

## 预发布部署流程（Phase 7）

取得具体主机、目标目录与预发布授权后，核查 CPU/内存/磁盘、Linux/Docker、端口、DNS/TLS、网络出口、对象存储权限和备份位置；记录只读结果。生产 DNS、小程序正式配置、生产数据变更另需明确授权，不在本轮范围。

先构建固定源码/锁文件镜像并扫描，准备秘密与私有目录，运行配置检查；备份已有预发布数据，显式执行兼容迁移，启动并测 API/Worker/存储/Provider、限额和告警。真实数据不用于自动测试。外部通知仅使用已经配置并获授权的渠道。

## 升级与回滚

迁移采用 expand/contract：先添加兼容结构，双读/转换需有记录，确认后才移除旧字段。每次升级记录旧/新代码与镜像、迁移计划、备份编号、前后数据计数/权限抽样。回滚镜像前确认 schema 兼容；不可逆迁移不盲目 reverse，进入维护并恢复到独立 DB 验证后切换。不能以删除数据库解决迁移失败。

迁移测试包括空库全量升级、从上一版本含代表性数据升级、重复 migrate、约束/版本/关联检查。种子显式且开发专用，不包含真实儿童或研发长文本。

## 备份与隔离恢复

备份集必须同一可验证切点：DB 快照/pg_dump、所有被引用的实际对象版本、对象清单/哈希/大小、部署/Schema/加密版本元数据。可选短暂冻结写入取得一致切点；单独 DB dump 加随意目录复制不算一致备份。备份加密异机保存，主密钥分管；保留期、目标 RPO/RTO 由部署策略确认。

恢复演练必须在新项目名、独立 DB/存储进行，禁止覆盖生产：

1. 默认停 Worker/Beat，关闭 Provider 出口；恢复 DB 和文件并校验哈希/清单。
2. 校验题目与图片关联、版本计数、两户/两孩子权限和抽样查看、题库许可/答案状态。
3. 重新应用独立删除/撤销清单，确认已删除数据不可读；外部保留政策另行披露。
4. 重建额度/预算结算和预留，未知费用保留待对账；queued/running/Outbox 不自动重放付费请求。
5. 用当前时间重新计算权益，不改 starts/expires；检查到期提醒幂等和已过期基础访问。
6. 验证版本密钥可解密必要凭证但不输出明文；测试旧/新主密钥策略和过期备份。
7. 记录耗时、数据量、差异与实际 RPO/RTO，确认后才允许显式恢复任务。

## 故障与密钥操作

队列积压先限流/观察 Worker、供应商和资源，不批量盲目重试。Provider 超时进入待对账，UI 展示当前模式与结果未知；预算不明停止新平台调用。Redis 故障不能跳过费用判断。DB 故障应 ready 503，不能用缓存代替安全账本。

Key 泄漏时先禁用调用、供应商侧撤销、轮换秘密/用户凭证，再审计相关任务和账单；不通过日志搜索输出完整秘密。主密钥更换需重加密和恢复可用性验证，见 [ADR-0003](../architecture/adr/0003-ai-credentials-and-budgets.md)。

数据删除先阻止访问与新任务，再清理原图、处理版、缓存、导出和分析。原生对象存储签名 URL 的有效期内撤销限制需明确；默认同源鉴权网关提供立即拒绝。备份按政策滚动清除，恢复重放 tombstone。到期降级与删除是完全不同的操作。

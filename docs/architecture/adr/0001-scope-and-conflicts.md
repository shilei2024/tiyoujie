# ADR-0001：阶段编号与本轮范围

日期：2026-10-22。状态：设计基线；不豁免真实验收。

## 背景

空目录允许从头设计；无需迁移已有项目。两份需求文件使用不同阶段粒度，且对 Phase 0 是否包含真实接入原型要求不同。差异明细见 [需求记录](../../development/requirements-and-conflicts.md)。

## 决策建议

本轮执行两份材料共同要求的盘点和方案设计，遵循开发说明的设计后停止边界。真实登录、私有文件链路和 Provider 原型在对应业务阶段完成，仍保留为关键门禁。Phase 0 设计检查通过后可以建设不触发外部收费的 Phase 1 骨架；整体状态 PARTIAL，不能宣称 PRD 的真实接入技术验证通过。

| 工程阶段 | 目标 | 对应 PRD 路线 |
| --- | --- | --- |
| 0 | 盘点、架构、威胁、验收计划 | PRD 0 的设计部分 |
| 1 | 骨架、容器、健康检查、CI | PRD 1 的前置设施 |
| 2 | 身份、家庭、授权、凭证、权益 | PRD 1 + PRD 0 登录验证 |
| 3 | 上传、OCR、校对、错题 CRUD | PRD 1 + PRD 0 私图/OCR 验证 |
| 4 | AI、Provider、混合费用闭环 | PRD 2 + PRD 0 图像 AI 验证 |
| 5 | 题库、来源、检索、数学验证 | PRD 2 |
| 6 | 练习、复习、报告、导出/删除 | PRD 3 |
| 7 | 安全、真实基准、恢复、预发布 | PRD 4 |
| 8 | 证据审查与负责人发布决定 | PRD 4 |

## 不采用的方案

不一次性铺开全部业务或用演示页面替代后端权限、数据、费用验证；不以 Mock 冒充真实接入；不为消除冲突自动放宽预算、版权或监护人授权。

## 后果

当前可审阅设计，尚无可操作产品。下一轮可以具体交付基础设施，但真实外部功能仍需要凭证、样本和微信配置。若产品负责人要求调整粒度，应修改阶段计划与追踪表，保持所有 P0 门禁。

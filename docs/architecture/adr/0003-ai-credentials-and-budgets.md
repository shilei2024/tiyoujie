# ADR-0003：混合 AI 的费用与秘密边界

日期：2026-10-22。状态：Accepted for design。实际实现/并发证明在 Phase 3–4。

## 模式绑定与秘密

每个 Job 创建时绑定 platform_trial 或 byok、家庭/孩子、Provider/Model/能力版本、告知版本和输入版本，不可原地修改。错误只返回可操作原因；不自动换模式或换凭证。官方端点由服务端维护，拒绝用户提交任意 URL；Worker 出口限制主机并禁止重定向。

平台 Key 从 Worker 专用秘密挂载或秘密服务读取，以 secret_ref 标识，不保存在数据库明文、镜像、Compose 文本或客户端。BYOK 归属用户且限定家庭，默认只允许本人调用；分享使用必须增加显式授权。家庭管理员能撤销风险配置，但不能读取或暗中使用其他成员的 Key。

BYOK 通过 HTTPS 提交，由凭证服务使用成熟 AES-GCM 认证加密；每条密文使用独立随机 nonce，AAD 包含 credential_id、family_id、provider_id、credential_version。存 ciphertext/nonce/key_version/掩码后缀；密钥版本材料独立秘密管理。普通接口、后台、导出均不可返回密文或明文。写入进程需加密能力，调用 Worker 需解密能力；单体进程隔离不能抵御 root/运行时控制者，必须如实披露。

凭证验证先尝试供应商授权元数据接口；需实际推理时明确提示这是用户账户费用并限制短文本/输出。验证连接不走平台额度，也纳入 BYOK 用量记录，不自动反复测试。

## 硬预算算法

1. 检查监护人授权、第三方告知、对象权限、任务限制、模式、Provider/Model、价格和能力。平台缺凭证、价格、日/月/全站/家庭任一强制配置时 fail closed。
2. 为每个请求构建**供应商费用的保守上界**：有界文本/图片输入、最大输出（含可计费推理）、最贵适用费率、缓存未命中及所有计费项。禁止联网工具和无法界定成本的供应商能力。无法计算可靠上界时不开放平台任务。价格按币种账本控制，不靠未版本化实时汇率换算。
3. 在 PostgreSQL 事务内按固定顺序锁定全站 lifetime、month、day 预算行，再锁家庭额度行；必要的初始窗口用唯一约束/重试创建。检查每项 `settled + reserved + upper_bound <= hard_limit`、家庭配额及熔断，原子写入预留、Job、Attempt、Outbox、额度事件。任一不满足则整体回滚，不发队列任务。
4. Outbox 至少一次投递，Worker 用执行租约和 fencing token 认领 Attempt；发送前重查用户授权、凭证版本、删除标记和熔断。熔断后未发送任务释放，已发送任务继续保留费用占用。
5. Worker 仅在持有有效预留时发送外部请求。Redis 只做队列/辅助限速，不能成为费用账本。API/Worker 崩溃、缓存丢失均不能重新创造余额。
6. 成功且用量完整时按固定价格版本结算实际值并释放差额；供应商未返回用量或连接超时后可能计费时，将预留转为待对账占用，不当作零费用。确定未发送/供应商确认未计费才释放费用预留。
7. 用户功能额度与平台费用分开：成功结果（包括 OCR 待校对）消耗一次；确定失败/取消按配置规则返还一次额度，供应商已有成本仍计入平台预算。唯一事件键保证重复回调不会重复返还或扣减。
8. 每次可能再次收费的重试新建 Attempt，重新预留费用上界；不得复用上一尝试已消耗预算。传输结果未知时暂停自动重试，避免重发收费。幂等账本不等于供应商 exactly-once。

日/月窗口用预算配置时区定义起止。接近边界时预留覆盖可能发送/结算落入的窗口，或在边界保护期暂停新发送；过期未发送的预留必须重绑新窗口并原子重审后才可发。所有尝试始终占用 lifetime 硬额。供应商账单结算周期可能不同，报表说明平台预算为内部发送口径，定期与供应商对账。

## 异常与恢复

实际金额高于上界、价格过期、账本不一致、供应商额外计费或无法对账：立即熔断新平台调用，保留真实费用并告警，人工审计恢复；不隐瞒超额。硬预算承诺建立在有效价格/可计费上界和平台专用账户前提上，供应商价格突变及控制台外部用量不能靠应用完全控制，应辅以供应商侧余额/限额。平台账号不得被其他未计量系统共用。

管理员恢复需专门权限、原因、配置版本及审计；暂停旧活动/重启服务不能清零预算。预算调小到低于已用/预留时立即熔断。告警可失败，硬限制不能依赖通知成功。

凭证替换原子增加 credential_version，未发送旧任务直接拒绝；已发送请求无法收回已使用密钥，记录 in_flight 并提示供应商侧撤销。删除使新调用立即不可用、清理密文；备份副本按轮换政策过期。主密钥轮换先加入新版本、重加密并验证数量/抽样、切换写入、保留受控旧版本供未过期备份恢复，不生成任何明文导出。

日志采用允许字段清单：request_id、对象 ID、状态、耗时、用量和估算；默认不记题干/图片/模型原始响应/请求体、Authorization 或 Key。异常与追踪 SDK 同样脱敏。Provider 错误不直接透传原始正文。

## 必须证明的性质

使用 PostgreSQL TransactionTestCase/独立连接屏障制造竞争，不用 SQLite 模拟锁：家庭/日/月/lifetime 各自最后一个名额的并发争夺、Outbox 重复投递、Worker 认领竞争、预留后崩溃、发送后超时、周期边界、重复结算、取消与完成竞争、管理员熔断和调低预算。被拒绝请求的 Provider 调用计数必须为零，已发送不明费用不自动退预算；平台与 BYOK 查询独立。
